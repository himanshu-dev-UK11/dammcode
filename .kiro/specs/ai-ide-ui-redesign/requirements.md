# Requirements Document

## Introduction

This feature delivers a premium UI redesign for the MyCodingMaster IDE. The scope is limited to visual presentation, layout organisation, spacing, and interaction chrome across the highest-impact surfaces: the main layout shell (activity bar, sidebar, top toolbar, status bar), editor tabs, and the AI Workspace dock panel. No functional or behavioural changes are made — every existing signal, slot, event-bus subscription, and data pathway is preserved exactly as-is. The design language draws from Material 3, Fluent Design, Linear, and Arc Browser: rounded corners (8–12 px), soft shadows, thin separators, minimal visual clutter, dark-theme-first palette, and excellent information hierarchy. All visual tokens are applied through `ui/design_system.py` and the global QSS stylesheet generated by `ui/theme.py`; hardcoded inline QSS strings inside individual widget files are replaced with design-system references.

## Glossary

- **DesignSystem**: The singleton `DesignSystem` instance returned by `get_design_system()` in `ui/design_system.py`, which owns all design tokens.
- **Radius**: The `Radius` class in `ui/design_system.py` that exposes border-radius tokens (`SM`, `MD`, `LG`, `XL`, `ROUND`).
- **Shadow**: The `Shadow` class in `ui/design_system.py` that exposes elevation shadow tokens.
- **Spacing**: The `Spacing` class in `ui/design_system.py` that exposes spacing-scale tokens.
- **ColorPalette**: The dataclass in `ui/design_system.py` holding all semantic colour tokens for a single theme.
- **ThemeManager**: The `ThemeManager` class in `ui/theme.py` that generates and applies the global QSS stylesheet.
- **ActivityBar**: The 44 px fixed-width leftmost strip in `MainWindow` containing emoji-icon navigation buttons.
- **Sidebar**: The collapsible explorer panel (default 220 px) sitting between the ActivityBar and the editor area.
- **TopToolbar**: The `TopToolbar` widget in `ui/top_toolbar.py`, a 30 px `QToolBar` row.
- **EditorTabBar**: The `QTabBar` inside `EditorTabs` (`ui/editor/editor_tabs.py`) that displays open-file tabs.
- **BreadcrumbBar**: The `BreadcrumbNavigation` widget rendered above the `QTabWidget` in `EditorTabs`.
- **AIWorkspaceDock**: The `QDockWidget` wrapping `AIEngineeringWorkspace` (`ui/ai_workspace/ai_engineering_workspace.py`), docked to the right at 280 px default width.
- **BottomStatusBar**: The `BottomStatusBar` widget in `ui/status_bar.py`.
- **SectionHeader**: The collapsible section-header widget inside `AIEngineeringWorkspace` (the `Section` component in `ui/ai_workspace/ai_workspace_panel.py`).
- **PremiumChrome**: The visual treatment applied to panel borders, title bars, and separators to achieve a professional, low-noise appearance — thin 1 px borders using `border_subtle` tokens, soft background contrast, and consistent corner radii.
- **InlineQSS**: Hardcoded stylesheet strings embedded directly inside widget Python files rather than generated through `ThemeManager`.

## Requirements

### Requirement 1 — Design Token Upgrade

**User Story:** As a developer working on MyCodingMaster, I want the design-system tokens to reflect a premium visual spec so that all redesigned surfaces share consistent, polished values without needing per-widget overrides.

#### Acceptance Criteria

1. THE DesignSystem SHALL expose `Radius` token values where `MD` equals 6 px, `LG` equals 8 px, `XL` equals 10 px, and `ROUND` equals 20 px, upgrading from the current smaller values.
2. THE DesignSystem SHALL expose `Shadow` token strings where `SM` is `"0 1px 3px rgba(0,0,0,0.12)"`, `MD` is `"0 2px 8px rgba(0,0,0,0.18)"`, `LG` is `"0 4px 16px rgba(0,0,0,0.24)"`, and `XL` is `"0 8px 24px rgba(0,0,0,0.32)"`, replacing the previous lighter values.
3. THE DesignSystem SHALL expose a `Spacing` token `LG` of 14 px, `XL` of 20 px, and `XXL` of 28 px to support tighter premium layouts.
4. WHEN `ThemeManager.apply_theme` is called with any supported theme name, THE ThemeManager SHALL regenerate the global QSS stylesheet using the updated `Radius`, `Shadow`, and `Spacing` tokens without requiring a restart.
5. THE DesignSystem SHALL maintain backward-compatible names and types for all existing `Radius`, `Shadow`, and `Spacing` class attributes so that no other module referencing those names requires modification.

### Requirement 2 — Main Layout Shell

**User Story:** As a user, I want the main window shell — activity bar, sidebar, toolbar, and status bar — to look like a professional engineering workstation so that I can focus on code without visual distraction.

#### Acceptance Criteria

1. THE ActivityBar SHALL be styled with background colour `ColorPalette.bg_secondary`, a 1 px right border using `ColorPalette.border_subtle`, and no other visible outlines or drop shadows.
2. WHEN an ActivityBar icon button is in its default (non-hovered, non-active) state, THE ActivityBar SHALL render each icon button with a transparent background, `ColorPalette.text_tertiary` icon colour, and a fixed 36 × 36 px hit target with `Radius.LG` corner rounding.
3. WHEN an ActivityBar icon button is hovered, THE ActivityBar SHALL change that button's background to `ColorPalette.surface_hover` and icon colour to `ColorPalette.text` within `Duration.FAST` milliseconds via QSS transition.
4. WHEN an ActivityBar icon button represents the currently active sidebar view, THE ActivityBar SHALL render a 2 px accent-coloured left-edge indicator bar (`ColorPalette.accent`) on that button and set its icon colour to `ColorPalette.text`.
5. THE Sidebar SHALL use `ColorPalette.sidebar` as background, have a 1 px right border using `ColorPalette.border_subtle`, and render the section-title label with `FontWeight.SEMIBOLD`, `FontSize.XS`, and `ColorPalette.text_secondary` using uppercase letter-spacing of 0.06 em.
6. WHEN the Sidebar is in its expanded state, THE Sidebar header toggle button SHALL display a left-pointing chevron glyph (`‹`) with size `FontSize.LG` and colour `ColorPalette.text_tertiary`, with no visible border.
7. WHEN the Sidebar is collapsed, THE Sidebar header toggle button SHALL display a right-pointing chevron glyph (`›`) with the same styling as the expanded state chevron.
8. THE TopToolbar SHALL be styled with a fixed height of 38 px, background colour `ColorPalette.toolbar`, a 1 px bottom border using `ColorPalette.border`, and zero visible side borders.
9. THE TopToolbar `QToolButton` items SHALL render with transparent background, `ColorPalette.text_secondary` text colour, `FontSize.SM` font size, `FontWeight.MEDIUM` weight, and `Radius.MD` rounding on hover background.
10. THE `ModelBadge` widget inside TopToolbar SHALL be styled with `ColorPalette.surface` background, a 1 px border using `ColorPalette.border`, `Radius.MD` corner rounding, and minimum padding of `Spacing.SM` vertical and `Spacing.MD` horizontal.
11. THE BottomStatusBar SHALL be styled with `ColorPalette.statusbar` background, a 1 px top border using `ColorPalette.border`, a fixed height of 24 px, and `FontSize.XS` for all `StatusChip` labels.
12. IF the active AI task state is "Thinking", THEN THE BottomStatusBar SHALL render the AI status `StatusChip` with `ColorPalette.accent` text colour and a pulsing opacity animation between 1.0 and 0.5 at `Duration.SLOW` ms per half-cycle.
13. THE ThemeManager SHALL include QSS rules for `QMainWindow::separator` with a width and height of 1 px and background colour `ColorPalette.border_subtle`, replacing any thicker default separator.

### Requirement 3 — Editor Tab Bar

**User Story:** As a developer, I want editor tabs to feel modern and uncluttered so that I can quickly identify the active file and navigate between open files without visual noise.

#### Acceptance Criteria

1. THE EditorTabBar SHALL be styled with tab height of 34 px, background `ColorPalette.bg_secondary` for inactive tabs, and `ColorPalette.editor_bg` for the active tab.
2. WHEN a tab is in its active (selected) state, THE EditorTabBar SHALL render a 2 px top accent bar using `ColorPalette.accent` on that tab only, with no border on the other three sides.
3. WHEN a tab is hovered and not active, THE EditorTabBar SHALL change that tab's background to `ColorPalette.surface_hover` within `Duration.FAST` milliseconds.
4. THE EditorTabBar SHALL use `FontSize.SM` and `FontWeight.MEDIUM` for all tab label text, with `ColorPalette.text_secondary` for inactive labels and `ColorPalette.text` for the active label.
5. WHEN a file has unsaved changes, THE EditorTabBar SHALL render a filled dot indicator (`●`, `ColorPalette.warning`) adjacent to the filename label instead of appending the raw `●` character as plain text, so the indicator is visually distinct from the label.
6. THE BreadcrumbBar SHALL be styled with `ColorPalette.bg_secondary` background, a 1 px bottom border using `ColorPalette.border_subtle`, `FontSize.SM` text, and `ColorPalette.text_secondary` colour for non-active path segments.
7. THE `QTabWidget::pane` SHALL have no visible border, and the background SHALL match `ColorPalette.editor_bg` so the tab content area is seamlessly joined to the active tab.
8. WHEN the InlineQSS inside `EditorTabs.setup_ui` references hardcoded hex colour values (e.g., `#181825`, `#1E1E2E`, `#89B4FA`), THE EditorTabs module SHALL replace those literals with `DesignSystem` palette token references so the tab bar honours all five themes.

### Requirement 4 — AI Workspace Dock (Premium Chrome)

**User Story:** As a user, I want the AI Workspace dock panel to look and feel like a first-class panel in the IDE so that working with AI feels integrated rather than bolted on.

#### Acceptance Criteria

1. THE AIWorkspaceDock title bar (`QDockWidget::title`) SHALL be styled with `ColorPalette.bg_secondary` background, `ColorPalette.text_secondary` title text at `FontSize.SM` and `FontWeight.SEMIBOLD`, a 1 px bottom border using `ColorPalette.border`, and vertical padding of `Spacing.MD` px.
2. THE AIWorkspaceDock close and float buttons (`QDockWidget::close-button`, `QDockWidget::float-button`) SHALL have transparent backgrounds, no borders in the default state, and a `ColorPalette.surface_hover` background with `Radius.SM` rounding on hover.
3. THE `AIEngineeringWorkspace` scroll area SHALL replace the hardcoded `background-color: #111113` and `#252528` scrollbar colour strings with `ColorPalette.bg` and `ColorPalette.border` token references respectively, maintaining the same 6 px slim scrollbar width.
4. THE `AIEngineeringWorkspace` container widget SHALL use `ColorPalette.bg` as its background colour, replacing the hardcoded `#111113` string.
5. WHEN a `SectionHeader` within AIEngineeringWorkspace is in its collapsed state, THE SectionHeader SHALL render with `ColorPalette.bg_secondary` background, a 1 px bottom separator using `ColorPalette.border_subtle`, `FontSize.SM` label text at `FontWeight.SEMIBOLD`, and a right-aligned collapse arrow in `ColorPalette.text_tertiary`.
6. WHEN a `SectionHeader` is hovered, THE SectionHeader SHALL change its background to `ColorPalette.surface_hover` within `Duration.FAST` milliseconds.
7. THE AIWorkspaceDock SHALL maintain its existing minimum width of 240 px and maximum width of 480 px without change.
8. IF the AIWorkspaceDock is floating (undocked), THEN THE AIWorkspaceDock SHALL display a 1 px border using `ColorPalette.border` on all four sides and `Radius.LG` corner rounding on the outer container.

### Requirement 5 — Inline QSS Elimination

**User Story:** As a developer maintaining the codebase, I want all widget-level inline QSS to be driven by design-system tokens so that a theme change applied through `ThemeManager` automatically propagates to every surface without manual per-file edits.

#### Acceptance Criteria

1. THE `MainWindow` setup_ui method SHALL apply ActivityBar and Sidebar background and border colours using `DesignSystem.palette` token references instead of hardcoded hex strings.
2. THE `TopToolbar` `_sep()` helper SHALL use `ColorPalette.border` instead of the hardcoded `#252528` colour string.
3. THE `TopToolbar` `WorkspaceStatus` label SHALL use `ColorPalette.text_tertiary` and `ColorPalette.text_secondary` instead of hardcoded `#52525C` and `#8E8E98` strings.
4. THE `TopToolbar` `ModelBadge` SHALL use `ColorPalette.surface`, `ColorPalette.border`, and `ColorPalette.surface_hover` instead of hardcoded `#1C1C1F`, `#252528`, and `#222226` strings.
5. THE `BottomStatusBar` `_separator_label()` helper SHALL use `ColorPalette.border` instead of the hardcoded `#252528` string.
6. THE `BottomStatusBar` `StatusChip` SHALL use `ColorPalette.accent` for accent state and `ColorPalette.text_secondary` for default state instead of hardcoded colour strings.
7. THE `AIEngineeringWorkspace` setup_ui method SHALL derive all background and scrollbar colours from `DesignSystem.palette` token references instead of hardcoded hex strings.
8. WHEN `ThemeManager.apply_theme` is called with a different theme name, THE ThemeManager SHALL trigger a repaint of all top-level widgets so that inline-QSS widgets that still reference palette objects reflect the new palette values.

### Requirement 6 — Non-Regression of Functional Behaviour

**User Story:** As a QA engineer, I want the redesign to leave every existing functional behaviour intact so that users experience no regressions after the visual upgrade.

#### Acceptance Criteria

1. WHEN the redesign is applied, THE MainWindow SHALL preserve all existing keyboard shortcuts (`Ctrl+B`, `Ctrl+\`, `Ctrl+Shift+P`, `Ctrl+\``) and their corresponding actions without modification.
2. WHEN the redesign is applied, THE EditorTabs SHALL continue to open, close, pin, unpin, duplicate, and reorder tabs with identical logic to the pre-redesign implementation.
3. WHEN the redesign is applied, THE AIWorkspaceDock event-bus subscriptions (`plan_updated`, `context_ready`, `tool_started`, `workflow_started`, `workflow_complete`, `workflow_failed`, and others) SHALL fire their existing handler methods unchanged.
4. WHEN the redesign is applied, THE BottomStatusBar event-bus subscriptions (`workspace_loaded`, `cursor_moved`, `tab_switched`, `task_started`, `task_completed`, and others) SHALL remain wired to their existing handler methods unchanged.
5. WHEN the redesign is applied, THE TopToolbar signals (`open_project_requested`, `run_requested`, `stop_requested`, `search_requested`, `command_palette_requested`, `model_selector_requested`) SHALL remain connected to their existing slots in MainWindow unchanged.
6. THE DesignSystem SHALL not rename, remove, or change the type of any attribute in `ColorPalette`, `Spacing`, `Radius`, `Shadow`, `FontFamily`, `FontSize`, `FontWeight`, or `Duration` that is currently consumed by code outside `ui/design_system.py` and `ui/theme.py`.
